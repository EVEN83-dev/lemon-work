# 评委体验指南 · Lemon One

> 目标：让评委在 10 分钟内看到“一个人 + 9 个 AI 员工”如何真实协作，并确认所有数字来自真实账本，而不是演示常量。

---

## 一、运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| Python | 3.12（或使用随包便携运行时） |
| 依赖 | `pip install -r requirements.txt` |
| 模型 | 本地 Ollama（默认）或 DeepSeek / 任意 OpenAI 兼容端点 |
| 账号 | 不需要注册；云端模型需评委自己的 API Key（可选） |

> 数字银行是本地模拟沙箱，不需要真实银行账号，不涉及真实资金。

---

## 二、最快体验路径（源码运行）

```bash
git clone https://github.com/EVEN83-dev/lemon-work.git
cd lemon-work
pip install -r requirements.txt
python yh_main.py
```

启动后：

1. 默认进入**标准模式**。
2. 点顶部「公司」胶囊，进入**公司模式**。
3. 首次进入会看到 9 张员工卡、左侧 KPI、底部 RUN LOG / DISPATCH / OUTPUT。
4. 点「管理」→「实时计划 / 历史会话 / 公司上下文 / 项目」。
5. 点「配置」→ 查看 9 名员工的模型 / API / 预算。
6. 点「＋ 上传策划书」→ 选择 md / txt / pdf / docx，真实读取正文并交给 CHIEF 拆解。

> 如果只想看 UI，不需要配置模型；如果要看真实执行，建议先配置本地 Ollama 或自己的 DeepSeek Key。

## 三、10 分钟评委检查点

### 1. 公司模式是真实组织，不是 9 张静态卡

- 9 张卡按部门分组，有汇报连线。
- 每张卡有状态、当前任务、token 环、技能/权限/上下文。
- 点任意员工卡，右侧抽屉显示：概览、技能、权限、上下文、消息、产出、事件。

**观察点**：员工卡数字、任务、会话来自真实账本；刷新后不回到演示常量。

### 2. 计划与审批是真实闭环

- 「管理」→「实时计划」：任务 ID、员工、类型、状态、token、耗时、结果。
- 上传策划书后，CHIEF 拆解出任务 DAG，并生成计划审批。
- 审批通过前，执行被审批门锁住；通过后才开始派发。

**观察点**：任务状态会随事件推进，不是一次性静态列表。

### 3. 实时统计可追溯

- 左栏 BUDGET：token 已用 / 预算 / API 余额。
- 顶栏 THRU：近 60 秒 token/s、事件/分、收束/分。
- 顶栏 CTX：上下文预算。
- 员工白盒「上下文」页：该员工 token 预算、按任务占比、上下文预算。

**观察点**：数字来自 SQLite 七表账本与引擎配置，不是前端写死。

### 4. 历史会话与公司上下文

- 「管理」→「历史会话」：全量台账、搜索、类型筛选、点击打开。
- 「管理」→「公司上下文」：owner 可编辑，保存后跨轮次共享，并注入子代理 DoD。
- 「管理」→「项目 / 公司」：多轮次列表、搜索、状态筛选、切换。

**观察点**：切换项目后，公司页全量数据源同步切换。

### 5. 配置员工

- 「配置」抽屉：全局模型、每员工模型、token 预算。
- 保存后回执“配置已保存”，并立即影响后续派发。

**观察点**：每名员工可以独立指定引擎/模型，不是全局一刀切。

### 6. 真实文件上传

- 「＋ 上传策划书」支持 md / txt / pdf / docx。
- md/txt 前端读取文本；pdf/docx 由后端提取文本。
- 上传后生成 brief artifact，并触发 CHIEF 拆解。

**观察点**：上传内容会真实进入 `artifact` 表；不是写入占位字符串。

### 7. 数字银行沙箱与安全闸门

- 标准模式下输入自然语言银行指令，Agent 调用银行技能。
- 高风险操作（转账、挂失、冲正、申购）弹出人工审批。
- 拒绝后明确“用户取消”；允许后审计留痕。

**观察点**：AI 负责跑腿，人负责点头；所有资金操作可审计、可回滚。

### 8. 多模态阅读

- PDF：文本提取；扫描件走 PyMuPDF 渲染 + 本地视觉模型 OCR。
- 图片：视觉模型识图 / 截图问答。
- 视频：优先字幕；无字幕时 faster-whisper 本地转写。

**观察点**：不是简单“读文件”，而是真实提取内容并进入 Agent 上下文。

## 四、已知边界（如实说明）

| 问题 | 现状 |
|---|---|
| 是否公网 SaaS | 否，当前是 Windows 桌面客户端 + 本地运行 |
| 是否真实银行 | 否，数字银行为纯本地模拟沙箱 |
| 历史会话正文 | 台账完整；部分旧会话的消息正文可能已被消息库清理，界面会如实提示 |
| 实时计划条数 | 当前展示最近 40 条任务快照；全量接口已存在，可继续切换 |
| 成本数字 | 按公开单价估算，仅参考，实际以 API 账单为准 |
| 模型能力 | 默认本地小模型；能力靠工程纪律、权限闸门和任务编排，不靠大模型堆参数 |

## 五、常见问题

**Q：没有 API Key 能体验吗？**
A：可以。UI、公司组织、账本、管理面板、历史会话都能看；真实执行需要本地 Ollama 或云端 Key。

**Q：会动到真实资金吗？**
A：不会。数字银行是本地 SQLite 沙箱，所有账户和行情均为虚构数据。

**Q：为什么公司页一开始是标准模式？**
A：默认进入标准模式是产品设计；点顶部「公司」胶囊即可进入公司模式。

**Q：数据存在哪里？**
A：`data/company/company.db`（七表账本）与 `session_mesh` 消息库；运行时数据不入 Git。
