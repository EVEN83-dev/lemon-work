## 0:00–0:20 开场：一句话讲清是什么

**画面**：桌面 → 双击 `启动LemonWork.bat` → 主窗口出现。

**口播**：
> 这是一个人的 AI 公司。你提出目标，9 个 AI 员工按组织架构协作，从策划、调研、开发、评审到交付，全程可视、可审批、可追溯。它叫 Lemon One。

**字幕**：柠檬一人公司 · Lemon One｜一个人的 AI 公司操作系统

## 0:20–1:00 进入公司模式：9 个员工，不是 9 张静态卡

**操作**：
1. 点顶部「公司」胶囊。
2. 展示 9 张员工卡、部门分组、汇报连线。
3. 鼠标扫过员工卡，展示 token 环、状态、当前任务。
4. 点 CHIEF 卡，打开右侧白盒抽屉。

**口播**：
> 公司模式里有 9 个角色：CHIEF 总管、PLANNER 规划、RESEARCHER 调研、BUILDER 构建、REVIEWER 评审、TESTER 测试、WRITER 写作、OPS 运营、AUDITOR 审计。每张卡不是装饰，背后是真实账本里的工位状态、任务和 token。

## 1:00–1:50 上传策划书：从一句话到任务图谱

**操作**：
1. 点「＋ 上传策划书」。
2. 选择一个事先准备好的 `demo_brief.md`（内容 3–5 行，例如“为一款面向中小企业的 AI 客服做竞品调研和 MVP 方案”）。
3. 点「上传并拆解」。
4. 展示 RUN LOG 出现事件、CHIEF 开始拆解、计划审批出现。

**口播**：
> 上传的不是占位文本，而是真实文件。md、txt、pdf、docx 都会被读取正文，生成 brief 产物，再由 CHIEF 拆解成任务 DAG。执行前会先进入计划审批，审批通过前不会派发。

**如果现场模型不可用**：只演示到“上传 → brief 产物 → 计划审批”，并说明“执行需要本地模型或云端 Key”，不要伪造执行结果。

## 1:50–2:40 白盒抽屉：每个员工都能被审计

**操作**：
1. 在 CHIEF 抽屉切换「概览 / 技能 / 权限 / 上下文 / 消息 / 产出 / 事件」。
2. 重点停在「上下文」：展示 token 预算、按任务占比、上下文预算。
3. 切到「权限」：展示能力矩阵。
4. 切到「事件」：展示真实事件流。

**口播**：
> 每个员工都是独立 Agent：有自己的模型、token 预算、技能白名单、权限矩阵和上下文。点开任何一层，都能看到它为什么能做、做了什么、还剩多少预算。

---

## 2:40–3:20 管理面板：计划、会话、上下文、项目

**操作**：
1. 点「管理」→「实时计划」：展示任务表、状态筛选、员工搜索。
2. 切「历史会话」：展示全量台账、搜索、类型筛选；点一条会话打开。
3. 切「公司上下文」：展示 brief、约束、预算、历史轮次；在文本框输入一句“本公司的交付标准：所有产物必须经过 REVIEWER 和 TESTER”，点保存。
4. 切「项目 / 公司」：展示多轮次列表、搜索、状态筛选、切换。

**口播**：
> 公司不是一轮就结束。计划、会话、上下文、项目都被管理起来。公司上下文会跨轮次共享，并真实注入后续子任务，而不是只存在界面上。

## 3:20–3:50 实时统计：每个数字都有来源

**操作**：
1. 回到公司页，指左栏 BUDGET：token 已用 / 预算 / API 余额。
2. 指顶栏 THRU：token/s、事件/分。
3. 指顶栏 CTX：上下文预算。
4. 拖动窗口从宽到窄，展示 3 列 → 2 列 → 1 列、底栏滚动、顶栏横向滚动。

**口播**：
> token、吞吐、余额、上下文预算都来自真实账本和引擎配置。窗口变窄时组件不会消失，而是重排并出现滚动轨道，保证数据仍然可读。

**注意**：不要展示真实 API 余额金额；只展示“已接入/查询中”或打码。

## 3:50–4:20 安全闸门：AI 负责跑腿，人负责点头

**操作**：
1. 切到标准模式，输入一条模拟银行指令（例如“查一下我所有账户余额，整理成表格”）。
2. 展示 Agent 调用银行技能、白盒过程。
3. 触发一条高风险操作（如模拟转账），弹出审批卡。
4. 点「拒绝」，展示“用户取消”；再点「允许」，展示审计事件。

**口播**：
> 资金类操作不是模型说了算。高风险动作必须人工审批，拒绝会明确取消，允许会留下审计记录。数字银行是本地沙箱，不碰真实资金，但流程是按真实金融场景设计的。
