## 13. 请尽量详细地介绍你的作品

### 一、作品定位

Lemon One 是一个 Windows 桌面级 AI 工作台。它不是一个“会聊天的助手”，而是一家**可运行、可管理、可审计的 AI 公司**：一个人提出目标，9 个角色 Agent 按组织架构协作，完成从策划、调研、开发、评审到交付的完整流程。

### 二、差异化亮点（我们和普通 AI 助手最大的不同）

1. **不是 9 个 prompt，是 9 个工位**：有组织架构、汇报关系、权限矩阵、技能白名单、token 预算和审批门；每名员工可独立配置模型、查看上下文、停止/重派。
2. **不是黑盒，是白盒**：任务 DAG、消息、工具调用、审批、越权拦截全部写入七表账本；每个数字都能追溯到真实来源。
3. **不是失控自动化**：资金类、不可逆操作必须人工审批；同级消息不构成授权；拒绝会明确取消，允许会留下审计记录。
4. **不是单一模型**：DeepSeek、Ollama、自定义 OpenAI 兼容端点；PDF/图片/视频阅读链完整。
5. **不是演示稿**：可运行的 Windows 桌面客户端，带实时吞吐、token、余额、上下文统计。

### 三、核心功能

1. **公司模式：9 个 AI 员工组成一家公司**
   - 角色：CHIEF（总管）、PLANNER（规划）、RESEARCHER（调研）、BUILDER（构建）、REVIEWER（评审）、TESTER（测试）、WRITER（写作）、OPS（运营）、AUDITOR（审计）。
   - 组织：部门、汇报关系、权限矩阵、技能白名单、token 预算、审批门、任务 DAG。
   - 账本：`company_run / agent / task / event / approval / artifact / session` 七表，所有状态可追溯。
   - 交互：左侧 KPI、中间员工图、底部 RUN LOG / DISPATCH / OUTPUT 实时看板；点员工卡打开白盒抽屉，查看技能、权限、上下文、消息、产出、事件。

2. **实时计划 / 历史会话 / 公司上下文 / 项目**
   - 实时计划：任务列表、状态筛选、员工搜索、token / 耗时 / 结果。
   - 历史会话：全量会话台账、搜索、类型筛选、点击打开。
   - 公司上下文：跨轮次共享，owner 可编辑，真实注入子代理 DoD。
   - 项目 / 公司：多轮次项目列表、搜索、状态筛选、一键切换。

3. **标准模式：日常 AI 工作台**
   - 多引擎：DeepSeek 云端、Ollama 本地、任意 OpenAI 兼容自定义端点。
   - 50+ 技能、工具调用、文件产物、历史会话、任务拆解。
   - 媒体阅读：PDF（含扫描件 OCR）、图片识图、视频字幕 / faster-whisper 本地语音转写。

4. **数字银行沙箱**
   - 自然语言办理 36 项模拟银行业务：余额、转账、对账、风控、审计、冲正、复利、基金/股票行情等。
   - 高风险操作必须人工审批；越权消息会被拦截并审计留痕。
   - 纯本地模拟，不涉及真实资金与真实金融机构。

5. **真实统计与配置**
   - token 已用 / 预算 / 总量。
   - 近 60 秒信息吞吐：token/s、事件/分、收束/分、活跃员工。
   - API 余额真实查询、上下文预算、引擎/模型按员工配置。
   - 配置抽屉支持 9 名员工模型 / API / 预算保存。

### 四、TRAE 在开发过程中提供的具体帮助

本轮参赛增量在 TRAE 中真实完成，主要包括：

1. **定位“公司页一直是演示态”的根因**
   - TRAE 读取公司页与桥接代码后，发现页面没有加载 `qwebchannel.js`，`window.__bridge` 一直是 `null`。
   - 进一步发现 `companyApi` 的 Qt 槽写成了 `@pyqtSlot(result=str)`，没有声明参数；前端带参调用时 Qt 按无参处理，恒返回空串。
   - 修复后公司页真实连桥，`real=true`，9 张员工卡来自真实账本。

2. **公司页响应式布局**
   - 3/2/1 列自适应、resize 重绘、缩放复位、顶栏横向滚动、底栏独立滚动、阶段条在矮视口保留。
   - 在 1400×900、1000×700、860×620 三种视口实机验证。

3. **新增四个管理面板**
   - 实时计划、历史会话、公司上下文、项目/公司。
   - 历史会话支持全量台账（1000 条已载入 / 台账共 2236 条）搜索、筛选、打开。

4. **补齐统计口径**
   - 近 60 秒 token/s、事件/分、收束/分、token 总量、活跃员工。
   - DeepSeek 余额接口真实查询（后台线程 + 缓存，不暴露 Key）。
   - 上下文预算、引擎/模型按员工展示。

5. **配置与上传**
   - 配置抽屉：9 名员工模型 / API / 预算保存。
   - 真实策划书上传：md / txt / pdf / docx 文本提取，不再写入占位内容。

6. **实机验证**
   - 通过 CDP 读取真实页面状态：`real=true`、9 张员工卡、重载后 JS 异常 0、console error 0。

### 五、创作过程中最深的经历

最深的一次，是排查“看起来都对了，但数据全是假的”。

公司页 UI 完整，卡片会动、按钮能点、数字在跳，但所有数据其实来自演示常量。我们先后怀疑后端、状态推送、前端渲染，最后才定位到两个很底层的问题：页面没有加载 QWebChannel 脚本；公司动作槽没有声明参数，导致前端每次带参调用都被 Qt 当成无参调用，返回值恒为空。

修复后，页面第一次显示 `real=true`，9 张员工卡、任务、会话、余额都来自真实账本。那一刻的感受是：AI 产品的可信度，不是界面多炫，而是每个数字都能追溯到真实来源。这也成为 Lemon One 后续所有统计和审批设计的原则——**不造数、不假成功、不可逆操作必须留痕**。
